DEEP LEARNING - ROADMAP
The full syllabus of this repository, in the order it should be learned.
================================================================================

--------------------------------------------------------------------------------
PREFACE
--------------------------------------------------------------------------------

So the syllabus below is not a list of things to know. It is a chain of
failures. The perceptron fails on XOR, so we stack layers. Stacked layers cannot
be trained by hand, so we need backpropagation. Backprop on deep stacks explodes
and vanishes, so we need better initialisation, activations and normalisation.
Trained networks memorise, so we need regularisation. Dense layers ignore that
pixels near each other are related, so we need convolution. Convolution cannot
carry information across time, so we need recurrence. Recurrence forgets, so we
need gates. Gates still force one bottleneck vector, so we need attention.
Attention makes recurrence unnecessary, so we get the Transformer. Read the
roadmap that way and the field stops being a catalogue of tricks.

Each topic in the repo follows the same layout:

    <topic>/
      theory/    plain-text notes - the primary artifact
      code/      from-scratch implementations that mirror the notes

Theory is written first. Code is written to match the notation and staging of
the notes, never the other way around.

--------------------------------------------------------------------------------
HOW TO READ THIS SYLLABUS
--------------------------------------------------------------------------------

Parts I to IV are the spine. They are prerequisites for everything after, and
should be read in order.

Parts V onward are the architecture families. They can be read in any order once
the spine is done, but the listed order is the historical and pedagogical one -
each family removes a limitation of the previous.

Parts XI to XIV are practice: how models are trained at scale, deployed,
compressed, and judged. They are not optional extras; a model that only exists
in a notebook is only half understood.
